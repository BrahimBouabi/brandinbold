## 3. Architecture Overview

### 3.1 BrowserEngine Interface
`electron/engine/BrowserEngine.ts` — the contract (KEEP UNCHANGED, user requirement):
```ts
interface BrowserEngine {
  readonly id: EngineId            // 'camoufox' | 'chrome-cdp'
  readonly name: string
  installedVersion(): Promise<string | null>
  ensureInstalled(onProgress?): Promise<void>
  launch(profile, userDataDir, ipInfo | null): Promise<{ result: LaunchResult; handle: BrowserHandle }>
}
```
`BrowserHandle` (`electron/engine/handle.ts`) is the engine-agnostic runtime surface the rest of the app talks to: `{ pid, debugPort, remote, cookies: {export, import, clear?}, openUrl(url), stop() }`.

Engines:
- **CamoufoxEngine** — `electron/engine/camoufox/CamoufoxEngine.ts` — **default, done, verified end-to-end** (native C++ fingerprinting via camoufox/fpgen, per-profile wrapper bundles, badge addon, session restore prefs, graceful stop). Uses `launchOptions()` from camoufox then `firefox.launchPersistentContext()` (playwright-core), or `Camoufox({persistent_context:true})` when no wrapper.
- **ChromeCdpEngine** — `electron/engine/ChromeCdpEngine.ts` — fallback, done (stock Chrome via CDP; JS-injection spoofing lives ONLY here; singleton-lock + DevToolsActivePort handling).
- **ChromiumEngine ("BoldBrowser")** — ❌ not started (interface is ready for it).

### 3.2 Data Layer
- **SQLite** via better-sqlite3 at `~/Library/Application Support/Brandinbold/rea.db` (dev: `…/Electron/rea.db`; one-time migration copies legacy DB if the new one is missing/<8 KB). Tables:
  - `profiles(id, name, status, group_id, deleted_at, created_at, updated_at, json)` — the full Profile doc is JSON in `json` (fields incl. os, color, proxy, proxyId, navigator, screen, webgl(+unmasked), canvas/canvasBlock, audio, timezone, geolocation, geoPolicy, webrtc, webglMeta, media(+mask), fonts, unicode, userAgentMode, dns, doNotTrack, hardwareConcurrencyOverride, deviceMemory, sessionLock, showNameInBrowser, uiFollowNavigatorLanguage, customArgs, startupUrls(+enabled), iphey, hideBrowserSettings, webcam, fillLanguageFromIp, freeProxy, extensions[], pendingCookies, fingerprint{drawnAt,engine,os,fpgen}, startup{homepage,restoreSession?,clearSession}, proxyLastCheck, pinned, disabled, legacy/extra/groupName/proxyProvider… via any-casts)
  - `groups(id, name, pinned, color, description, created_at)` (migration adds color/description to older DBs)
  - `proxies(id, name, created_at, json)` — proxy library (ProxyEntry: type http/https/socks5, rotating, tags, lastStatus, lastIpInfo)
  - `settings(key,value)` — one `app` row = AppSettings JSON (theme, language, engine, maxProfiles, automation*, browser toggles, user{name,email}, …; DEFAULT_SETTINGS in shared/types.ts)
- **Soft delete**: `profiles.deleted_at` → Trash; restore/purge IPC.
- **Per-profile user-data-dirs**: `…/Brandinbold/profiles/<profileId>/` (Firefox profile: cookies.sqlite, places.sqlite, sessionstore-backups/, storage/, extensions/).
- **Session restore** (Firefox prefs set per launch): `browser.startup.page=3`, `browser.sessionstore.resume_from_crash=true`, `max_resumed_crashes=-1`, `interval=15000`, `privacy_level=0`; graceful stop = `context.close()` with 10 s timeout → SIGTERM fallback; stale `lock`/`.parentlock` cleaned pre-launch; per-profile "clearSession" wipes `sessionstore-backups/` before launch.
- Restore-prefs are only applied when `profile.startup.restoreSession !== false` (tri-state; global default in Settings → Browser, `restoreSessions: true`).

- i18n: `src/i18n.ts` + `src/locales/{en,fr,es,pt,ru,zh,vi}.ts` — en complete; others cover nav/profiles/common (fallback en). Switch via user menu or Settings (persisted `settings.language`).

## 5. Bugs Known and Open

### BUG-001 – Window-title patch is best-effort and unverified (P3)
- Observed: title suffix may stay "Camoufox" instead of the profile name.
- Cause: `patchWindowTitle` (badgeExtension.ts) rewrites `-brand-full-name` inside the cloned bundle's omni.ja; silently skips if the zip entry layout differs.
- Fix location: `electron/engine/camoufox/badgeExtension.ts`. Verify by launching and reading the title.
- Status: open (P3 — Dock/menu bar already show the profile name).

### BUG-002 – BrowserScan classifies the engine as "Antidetect Browser" (P3, inherent)
- Observed: category label on browserscan.net despite authenticity 100 %.
- Cause: Firefox family + RFP patterns; not fixable on a Firefox engine.
- Status: accepted trade-off (documented in comparison).

### BUG-003 – Per-profile dock icon only on macOS (P2)
- Observed: Windows/Linux launches use the stock camoufox icon/name.
- Fix location: `electron/engine/camoufox/profileApp.ts` (returns null off-macOS) — Windows needs a launcher .exe, Linux a .desktop generator.
- Status: open (P2).

### BUG-004 – Cookie collector is minimal (P3)
- Observed: visits 5 hard-coded sites, no per-site waits config, no "robot" UI.
- Fix location: COLLECTOR_SITES + `cookies:collect` in `electron/main.ts`.
- Status: open (P3).

### BUG-005 – Stale running-state edge case (P3)
- Observed: if the whole Brandinbold app is SIGKILLed, the orphan Firefox stays alive; on relaunch the profile shows Ready in the registry but launching hits Firefox's own singleton → engine reports "already running outside this session" (handled error, but the orphan must be stopped manually via Activity Monitor or by launching+stopping once).
- Fix location: `electron/engine/camoufox/CamoufoxEngine.ts` (could auto-adopt/kill orphans by profile-dir pgrep at launch).
- Status: open (P3; message guides the user).

### BUG-006 – CSV round-trip cosmetic diffs (P3)
- Observed: accuracy `1622.0` → `1622`; 9 documented non-identical columns in round-trip (UA/version/hashes/dates — by design).
- Fix location: `electron/csv/incognitonCsv.ts` (accuracy String formatting) if ever needed.
- Status: documented, accepted.

### BUG-007 – "Export to CSV" in row menu when engine=Chrome (P3)
- Observed: works, but Incogniton-format export of a Chrome-engine profile exports `userAgentMode` flags that only make sense on Camoufox. Cosmetic.
- Status: accepted.

## 9. Key Decisions and Rationale

### Decision: Camoufox (patched Firefox) as the primary engine
- Why: fingerprinting is applied in C++ inside the browser (invisible to page JS), coherent fpgen identities, geoip-native timezone/locale/geo/WebRTC alignment, npm package (no Python), Playwright-compatible.
- Trade-off: Firefox family (no CDP, no client hints, no Chrome Web Store extensions, BrowserScan "Antidetect" category label). Accepted.

### Decision: Do NOT copy Incogniton code; RE only for architecture
- The jar was decompiled for architecture/feature reference (endpoints, launch pipeline, data model). All Brandinbold code is original. Their `--encodeddata` server blob and patched-Chromium approach were consciously replaced by camoufox+fpgen.

### Decision: BrowserEngine interface + BrowserHandle abstraction
- Engines are pluggable; manager/UI never see engine specifics (stop/cookies/openUrl are handle methods). ChromeCdpEngine retained as fallback.

### Decision: Pin the fingerprint once per profile
- fpgen identity drawn once, persisted in the profile (`fingerprint.fpgen`), replayed every launch — same UA/WebGL/canvas across sessions. Only "Get New Fingerprint"/OS change redraws.

### Decision: Separate browser UI locale from navigator.language
- `intl.locale.requested=en-US` always (except explicit per-profile opt-in `uiFollowNavigatorLanguage`, default OFF); page-world locale via Playwright `locale` context option. Fixes the Arabic/RTL/garbled bug.

### Decision: Cross-OS = host fonts
- Identity OS ≠ host OS ⇒ `custom_fonts_only` + host font families (garbled-UI fix); UA/platform/WebGL stay foreign; canvas protection auto-covers pixel readback. Warning shown in the form.

### Decision: Profile badge as a per-profile baked WebExtension
